ASVS Level 1 — PASS (Post-Remediation) NetWolf passed all applicable OWASP ASVS Level 1 requirements after remediation. All 5 findings identified during the assessment have been resolved. 11 requirements were deemed not applicable due to the static single-page application architecture (no server-side code, no cookies, no file uploads).
📋 Findings & Remediation
V3.3.2 — SESSION MANAGEMENT
No session idle timeout
Sessions remained active indefinitely after login with no inactivity timeout. A user who left a browser open on a shared machine would remain authenticated without limit.
Remediated: An 8-hour idle timeout was implemented. Activity is tracked on click, keydown, mousemove and touch events. Inactive sessions are automatically signed out via Firebase signOut().
V3.7.1 — SESSION MANAGEMENT
No re-authentication for sensitive actions
Sensitive actions (clearing the Groq API key, deleting IP mappings) did not require re-authentication, allowing anyone with access to an unlocked browser to perform these actions.
Accepted Risk: NetWolf does not store business-critical data or process financial/health information. The Groq key and IP mappings are the only sensitive items, both clearable only after authenticated login. Rated Low risk for this application type. Re-authentication would be implemented if higher-sensitivity features are added.
V14.2.1 — CONFIGURATION
Firebase SDK not on latest version (10.12.0)
The Firebase JavaScript SDK was pinned to version 10.12.0, which may contain security patches released in subsequent versions.
Remediated: Firebase SDK updated to 10.14.1 in both script references (firebase-app-compat.js and firebase-auth-compat.js).
V14.4.4 — HTTP SECURITY HEADERS
Missing X-Content-Type-Options: nosniff
The X-Content-Type-Options: nosniff header was absent, allowing browsers to MIME-sniff content types which can lead to content injection in older browsers.
Remediated: Added <meta http-equiv="X-Content-Type-Options" content="nosniff"> to the HTML head. Note: for full effectiveness this should also be set at the hosting/Cloudflare level as an HTTP response header.
V14.4.5 — HTTP SECURITY HEADERS
HSTS not set in HTML (hosting-level control)
The Strict-Transport-Security header cannot be set via HTML meta tags — it must be configured at the web server or CDN level. This ensures all connections use HTTPS.
Action Required (Hosting Level): Enable HSTS in Cloudflare or your hosting provider: Strict-Transport-Security: max-age=31536000; includeSubDomains. This cannot be fixed in app.html — it is a server configuration item.

⚡ One Remaining Action — Hosting Level
ACTION REQUIRED — CLOUDFLARE / HOSTING
Enable HSTS and verify HTTP response headers
The following cannot be set in HTML and must be configured at your hosting provider or Cloudflare:
In Cloudflare → SSL/TLS → Edge Certificates:
Enable "HTTP Strict Transport Security (HSTS)" — minimum max-age 6 months

In Cloudflare → Rules → Transform Rules → Response Headers:
Add: X-Content-Type-Options: nosniff (as HTTP response header, not just meta tag)
Add: Strict-Transport-Security: max-age=31536000; includeSubDomains
